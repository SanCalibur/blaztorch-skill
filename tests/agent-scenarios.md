# Agent判断的人工验收案例

以下用于在使用本技能的agent会话中检验判断责任，不由固定脚本执行或打分。脚本只应完整传递所列来源记录，agent阅读`SKILL.md`及相关参考后给出有依据的答复。

1. **报名截止但仍在提交**：当前为2026-11-12，来源的报名截止为11-10、作品截止为11-20，用户尚未报名。agent应区分两种日期，不因官网“未结束”标签直接建议报名。若用户明确已报名，讨论继续参赛的准备。
2. **日期有值但时区不明**：来源只有11-12截止，无具体时区或时刻。agent不补23:59、不声称还剩精确小时，核对原规则或标记待确认。脚本保留日期字段，不自动归为已结束或开放。
3. **能力证据不足**：用户只说跟教程改过网页，没提到数据或部署。agent保留未知，对影响推荐的缺口询问；不能把缺失证据判为0分，也不按关键词设置固定能力门槛。
4. **赛题禁止AI编码**：用户想练习模型API，比赛页面明确禁止AI辅助编码。agent应说明工具规则及与用户目标的关系，不直接因标题含AI就推荐。
5. **同URL多条获奖记录**：两个不同ID指向同一作品URL，分别关联不同赛事。脚本两条都返回。agent判断是否同一作品，并保留各场获奖记录；不能把两条记录当作两种独立创意凑数。
6. **来源相互冲突**：官网状态写即将开始，但公开日程已过提交截止，另有正式结果出处。agent核对来源与当前时间，解释所采纳的依据，不盲从任何单个标签。脚本不得提前删除、修正或裁定这些来源字段。
